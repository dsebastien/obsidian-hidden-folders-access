# 2026-11-24

Fast restarts: keep the metadata of hidden files across Obsidian restarts (issue #16).

## Accomplished

- Diagnosed a startup freeze of about 9 minutes in a vault with a 700-file `.claude` folder. Cause: `MetadataCache.initialize()` deletes the file-cache entries of paths that the vault scan did not find, and the scan skips dot-folders. Each re-injected file was read, hashed, re-parsed and fired `changed` again, at about 215 ms of main-thread time per file (Obsidian 1.15.1, 63 plugins). The slowest listeners were core Backlinks `updateBacklinks` (on `resolved`, 56 ms per file) and Various Complements (on `changed`, 40 ms per file).
- Added `services/metadata-cache-snapshot.ts`: persist `[path, mtime, size, hash]` of the markdown files below enabled folders in `app.saveLocalStorage`, restore them into `metadataCache.fileCache` in `onload` and before each cascade, prune the ones that no file claimed.
- Measured in a live vault, 30 files per case: full re-parse 215 ms per file, cache hit after restore 7.5 ms per file.
- Updated `documentation/Architecture.md` and `docs/tips.md`.

## Decisions

- localStorage, not `data.json`: synchronous (safe in `onunload`), per vault, and not synced or committed with the plugin folder.
- Restore in memory only, not to IndexedDB: Obsidian drops the entries again at the next startup anyway.
- Restored files no longer fire `changed` at startup, the same as unchanged regular files. They still fire vault `create` and metadata `resolve` / `resolved`, and their metadata is available in `create` handlers.

## Open questions

- A plugin that builds its index only from its own startup scan plus `changed` events no longer sees unchanged hidden files after a restart. Regular vault files behave the same way, but before this change hidden files were always reported through `changed`. To verify with the plugins in daily use.
- Needs a manual runtime check: restart Obsidian twice with a large hidden folder enabled, and make sure that the second start shows the files in the tree, Bases and search without the long freeze.
